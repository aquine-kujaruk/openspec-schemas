# Architecture review

What no linter can decide about the architecture: the judgement rules. `factory review` asks them to a decision model, apart from the verdict of `factory check`.

### Reviewer rubric (not lintable; judged by `factory review`)

Each row carries the yes/no question `factory review` asks the decision model and the layers (a folder or subfolder, `domain/value-objects`) it is asked over; a row marked `across files` needs more than one file to be judged and is left to the human reviewer. A question is generic: it names no package of the project's `package.json` and no word of the product vocabulary. The pass record keeps the hash of these rows (id, question and layers): changing a question judges every file again on the next pass.

Product vocabulary (each word is matched at the start of a word; a question that names one is rejected): `payment`, `cart`, `order`, `invoice`, `coupon`, `return`, `report`, `notification`, `profile`, `auth`, `session`.

| ID  | Rule | Question (yes/no; the model reads it) | Layers |
| --- | ---- | ------------------------------------- | ------ |
| S05 | A repository returns primitives or schema props; the use case hydrates them into domain objects | Does this repository implementation build domain objects (entities, aggregates, value objects) and return them, instead of returning primitives or schema props? | infrastructure/repository-implementations |
| S06 | The canonical representation of a value object (`Money.format`) belongs to the domain. Sums with money go through the value object's methods; the currency comes from `Currency`, never from a literal. A fixed locale in an entity is a smell | Does this file compute with money outside the value object's methods, take a currency from a literal, or fix a locale inside an entity? | domain |
| S07 | A use case is tested through its acceptance test, with no delivery mechanism (`no-tests-in-src`); a repository has an integration test over an in-memory adapter that implements its real ACL | Is a use case or a repository left without the test the architecture asks for (a use case with its acceptance test, a repository implementation with an integration test over an in-memory adapter)? | across files |
| S08 | What **two modules** use lives in `shared`: session, Money, the base HTTP adapter. A clone the duplication check finds between two modules is an S08 warning (`duplication-below-threshold`) | Is something two modules both use kept inside one of them instead of in the shared module? | across files |
| S09 | A domain or application name says what happens in the business, never which technology or provider does it (`PaymentException`, not `StripeException`; the provider's error goes in `cause`) | Does this file name a technology, library or provider in a class, exception, method or variable name instead of what happens in the business? | domain, application |
| S10 | Raw external data is typed as an unknown record until the ACL validates it; it never travels further as such | Does raw external data travel beyond the anti-corruption layer without being typed as an unknown record and validated first? | infrastructure |
| S11 | An aggregate exists only when several entities and value objects form a higher-order concept; never by obligation (a module may have none) | Does an aggregate exist that composes no higher-level concept out of several entities and value objects? | across files |
| S12 | A domain service is the last resort after an instance method and a static one; shared by the objects of one module it stays in the module, shared by several it goes to `shared` | Does this domain service hold a rule that could be an instance method or a static method of one of the domain objects it takes? | domain/services |
| S13 | A repository method takes the most expressive verb that hides the logic underneath (`infer`, `search`); basic verbs only when nothing better fits | Does a repository interface method use a basic verb where a more expressive verb that names the logic underneath would fit? | application |
| S14 | An emergent object moves to `shared/infrastructure` when more than two modules use it; before that, the rule of three applies | Is an emergent infrastructure object used by more than two modules still kept in one module instead of the shared module? | across files |
| S15 | The shape a consumer needs is a method of the domain object that serializes or reduces it; there is no DTO | Does this file copy fields out of a domain object into a plain object or type made for one consumer (a DTO, a response shape, a mapper), instead of calling a method of the domain object that serializes or reduces it? A schema, its inferred props type, a repository interface, the file's own state type or an adapter's raw record does not count. | application, infrastructure |
| S16 | A constructor flag that picks between two schemas (`forRead`) is two parsing paths in one object: a read schema derived in the schema's file, or parsing at the boundary | Does a constructor take a flag that selects between two schemas or two parsing paths? | domain |
| S17 | A value object without behaviour asks whether it is a concept or a wrapper | Is this value object a bare wrapper: a class that only stores and returns its value, with no method of its own that validates, compares, formats or derives something (the constructor and plain getters do not count)? | domain/value-objects |
| S18 | A use case that only forwards to a repository is still a candidate for an atomic use case, never for an application service | Is this use case shaped as an application service with several unrelated methods instead of one atomic use case with an `execute` method? | application |
| S19 | The use case hydrates into domain objects what it reads from the repository; it never passes raw props on | Does this use case pass on primitives or schema props it read from a repository without turning them into domain objects first? | application/use-cases |
| S20 | The why lives in the artifacts (specs, plan); code carries no comment that repeats them or repeats what the code itself says | Does this code contain a comment (a `//` line or a `/* */` block) that only restates what the code says, or narrates a requirement, a decision or a contract? If it has no comment at all, the answer is no. | domain, application, infrastructure |
