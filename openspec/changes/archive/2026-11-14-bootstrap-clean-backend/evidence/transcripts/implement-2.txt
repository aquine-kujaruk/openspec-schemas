# infrastructure

**Owns:** `src/<module>/infrastructure/` except `adapters`: `repository-implementations`, `acl`, and the emergent folders the configuration admits, such as `paginators`; and `test/integration/<module>/` (one `<x>-repository.test.ts` per repository implementation). The adapters are the `adapters` workstream.

**Receives:** the repository interfaces of `app-domain` (it implements them exactly) and the domain props and exceptions they name. The ACLs it declares are seams that `adapters` implements. The change's design fixes both, with the record → props mapping one line per field and the domain exception for each failure of the resource.

**Fakes:** the adapter, and only it. The ACL is real: its interface and its record schemas (the schema package) say which attributes the system needs and validate them. The integration test builds `new XRepositoryImplementation(new InMemoryXAdapter(records))`, where the in-memory adapter implements that ACL: the product's `in-memory-<x>.adapter.ts` once `adapters` has built it, or a class inside the test until then. Without the real adapter, repositories and ACLs are pure code: map records to props, raise domain exceptions. A repository or adapter throws only the exceptions of its own module (or `ValidationException`), with the resource's error in `cause`; a shared adapter such as `HttpApiAdapter` receives from the module adapter the exception to throw.

## How

1. Read the `## reference` of `infrastructure.examples.md` and `integration.examples.md`.
2. Per resource: the ACL (record schema and interface) is already fixed; write the repository implementation over it. A repository never imports an adapter or does `new XAdapter(`: the composition root injects it.
3. Per repository implementation, write `test/integration/<module>/<x>-repository.test.ts`: the mapping of every field the design names and the exception for every failure. Invent the records inside the ACL's schema, taking the Examples of the product specs as a guide where values overlap; no fixture comes from the artifacts. When the behavior changes, rewrite the test inside the same seams.

**Check:** `pnpm exec factory check --workstream infrastructure [--module <module>]`, plus `pnpm exec factory test integration`.

# List customer orders

## Goal

Provide a query returning a customer's orders with id, customer id, total in cents and placement date, newest first. Deliver the use case and domain with acceptance coverage first; then connect the repository, anti-corruption layer, HTTP and development adapters, and entry.

## Decisions

- Use the `orders` module and `ListCustomerOrdersUseCase.execute(customerId)` returning order props, rather than introducing an inbound web server the request does not require.
- The application sorts by placement instant descending, rather than relying on backend ordering; equal instants have no additional public ordering guarantee.
- Return a complete array without pagination, rather than inventing a paging protocol absent from the service contract.
- Keep placement dates as validated ISO timestamp strings in props and compare their parsed instants, rather than comparing strings or exposing mutable Date objects.
- Map resource records to domain props in the repository; retain snake_case only in the ACL and adapters, rather than letting the service vocabulary enter the use case.
- Use `NODE_ENV=development` for the in-memory backend (empty by default, constructor-seedable); all other environments use HTTP and require `ORDERS_API_URL`, rather than silently falling back to development data.
- Translate invalid records to `ValidationException` and resource/configuration failures to `OrdersUnavailableException` with the original error as cause; reject the query rather than returning partial data or disguising failure as an empty list. No retry policy or public HTTP error status is introduced.
- Use generated acceptance tests with a fake repository in phase 1 and repository integration tests with an ACL-typed in-memory adapter in phase 2, rather than real network calls in local tests.
- The cents architecture decision below is explicitly requested by the user; it is already authorized.

## Architecture decisions

### Decision: money-in-integer-cents · Money amounts use integer cents

@adds @area:product @topic:money @applies:domain,application,infrastructure,adapters @enforced:domain-and-acl-schemas,integration-tests,review

Money amounts SHALL be represented as integers in cents across the product. `OrderProps.totalCents` and service `total_cents` SHALL carry the same cents value without division, rounding or conversion into floating-point major currency units. JavaScript number values SHALL pass safe-integer validation so the representation preserves exact cents.

**Why** The user explicitly requires integer cents; retaining that unit avoids rounding and unit ambiguity at boundaries.

**Alternatives** Decimal major units and floating-point currency values are discarded because they weaken the required representation.

**Consequences** Future money fields must preserve this unit. Values outside the safe-integer range are rejected, not rounded. Currency, sign restrictions and exchange rates are outside this decision.

The ACL schemas validate the actual JSON array and required fields, including safe-integer cents and valid timestamps. Extra service attributes need no domain equivalent. Record → props mapping is explicit:

- `customer_id` → `customerId`, unchanged.
- `total_cents` → `totalCents`, unchanged integer cents.
- `placed_at` → `placedAt`, unchanged timestamp.

The repository receives only `OrdersAcl`, imports no adapter, maps validated records, validates props, and filters by requested customer id so another customer's orders cannot escape the query. There is no empty-list fallback on failure. The in-memory adapter validates and returns seeded resource records for the customer; it is distinct from the acceptance repository fake. # adapters

**Owns:** `src/<module>/infrastructure/adapters/` and `src/shared/infrastructure/adapters/` (the base adapters every module composes, such as `http-api.adapter.ts`).

**Receives:** the ACLs of `infrastructure` (`acl/<name>.acl.ts`: `interface <Name>Acl` and the schemas of its records), fixed before this workstream starts, and the domain exceptions an adapter throws. The ACL is the seam: a repository implementation receives an adapter typed by it and never imports or constructs one, so this workstream and `infrastructure` are built apart.

**Fakes:** nothing. Adapters are the edge; behind them is the real resource.

## How

1. Read the `## reference` of `adapters.examples.md`.
2. Per ACL: one adapter per backend (`http-<name>.adapter.ts`, `in-memory-<name>.adapter.ts`), each a class that `implements <Name>Acl`, and `<name>.adapter.ts`, which picks one by environment and exports the ACL-typed instance (`export const <name>Adapter: <Name>Acl`). Every ACL needs at least one adapter.
3. Speak the resource's shape: parse through the ACL's record schemas, never a domain schema. Translate the resource's failures into domain exceptions with the caught error as `cause`.

No product tests for now: the rules are the check. Contract tests against the real services (testcontainers or similar) are a later decision; when they come, they belong here.

**Check:** `pnpm exec factory check --workstream adapters [--module <module>]`.

export class HttpApiAdapter {
  constructor(private readonly baseUrl: string) {}
  async get<S extends z.ZodType>(
    path: string,
    schema: S,
    fail: (response: Response) => DomainException,
  ): Promise<z.output<S>> {
    const response = await fetch(`${this.baseUrl}${path}`);
    if (!response.ok) throw fail(response);
    return schema.parse(await response.json());
  }
  async find<S extends z.ZodType>(
    path: string,
    schema: S,
    fail: (response: Response) => DomainException,
  ): Promise<z.output<S> | null> {
    const response = await fetch(`${this.baseUrl}${path}`);
    if (response.status === 404) return null;
    if (!response.ok) throw fail(response);
    return schema.parse(await response.json());
  }
}

# clean-architecture

**Reduces:** the workstreams the topology lists under it (by default `app-domain`, `infrastructure` and `adapters`).

**Owns:** the cross-module rules (`modules.rules.ts`): modules do not import one another, `shared` imports no module, no cycles, every file in a zone, no tests in `src`, no `any` and no raw errors in the core, and no escape from the harness (a lint rule disabled, a type error suppressed or expected, a cast through `unknown`). It also owns the entry (`src/main.ts` by default), the composition root: the only place that builds adapters, repositories and use cases together.

## How

1. Merge the upstream workstreams' work. A conflict can only be at a seam: if both sides changed a repository interface or an ACL, the seam was not fixed first; settle it on what the consumer needs (the use case for a repository interface, the repository implementation for an ACL) and adapt the other side.
2. Run the check. This is where it shows whether each map workstream built what its spec, its skill and its seams asked for. A failure names the workstream: go back to it and fix it there, keeping the seams and the artifacts as they are, then run this check again. A decision the artifacts do not settle and you cannot take goes to the person, as the implement skill says.
3. Fix what crosses modules: move what two modules share into `shared`, break cycles.

**Check:** `pnpm exec factory check --workstream clean-architecture [--module <module>]`, which includes every upstream workstream's check.

import { orderRecordsSchema, type OrdersAcl, type OrderRecord } from \"../acl/orders.acl\";
import { OrdersUnavailableException } from \"../../domain/exceptions/orders.exceptions\";
import { ValidationException } from \"../../../shared/domain/exceptions/validation.exceptions\";
export class HttpOrdersAdapter implements OrdersAcl {
  private readonly baseUrl: URL;
  constructor(baseUrl: string) {
    try {
      const url = new URL(baseUrl);
      if ("'!["http:", "https:"].includes(url.protocol) || url.search || url.hash || url.username || url.password) {
        throw new OrdersUnavailableException({ cause: url });
      }
      url.pathname = url.pathname.replace(/'"\\/+"'$/, "") + "/";
      this.baseUrl = url;
    } catch (cause) {
      if (cause instanceof OrdersUnavailableException) throw cause;
      throw new OrdersUnavailableException({ cause });
    }
  }
  async listCustomerOrders(customerId: string): Promise<OrderRecord[]> {
    let response: Response;
    try {
      response = await fetch(`${this.baseUrl.href}customers/${encodeURIComponent(customerId)}/orders`, { method: "GET" });
    } catch (cause) {
      throw new OrdersUnavailableException({ cause });
    }
    if (!response.ok) throw new OrdersUnavailableException({ cause: response });
    let raw: unknown;
    try {
      raw = await response.json();
    } catch (cause) {
      throw new ValidationException("Orders JSON", cause);
    }
    const result = orderRecordsSchema.safeParse(raw);
    if (!result.success) {
      const cause = result.error;
      throw new ValidationException("Orders", cause);
    }
    return result.data;
  }
}
